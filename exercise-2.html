🛒 SmartShop — Django Messages, Sessions & Cookies

Build one Django application using Django Templates. The application uses a session-based shopping cart, one-time Django messages, a session visit counter, and cookies for display-name and theme preferences.

1. What You Will Build

Browser → Django URLs → Views ├─ Messages ├─ Sessions ├─ Cookies └─ Context ↓ Django Templates

Core idea: messages provide temporary feedback; sessions remember server-side visitor state across requests; cookies store small pieces of information in the browser.

2. Why Sessions and Cookies?

HTTP is stateless. A later request does not automatically remember an earlier request. A shopping cart therefore needs a mechanism for remembering what happened.

FeaturePurposeExample
MessagesTemporary feedbackProduct added successfully
SessionVisitor-specific state across requestsShopping cart
CookieSmall browser-side valueTheme preference

9. Session Visit Counter

def home(request):
    visits = request.session.get("visits", 0) + 1
    request.session["visits"] = visits
    return render(request, "store/home.html", {"visits": visits})

request.session.get("visits", 0) reads the current value or returns 0 if it does not exist. Assigning to request.session[...] saves session state.

Create home.html:

10. How Sessions Work

Browser │ session identifier cookie ▼ Django │ finds corresponding session ▼ Server-side data {"visits": 3, "cart": [1,2]}

A session and a cookie are not the same thing. With the default database-backed session setup, Django stores session data server-side and uses a browser cookie containing a session identifier to associate requests with that data.

12. Add to Cart: Sessions + Messages

from django.shortcuts import render, redirect
from django.contrib import messages

def get_product(product_id):
    for product in PRODUCTS:
        if product["id"] == product_id:
            return product
    return None

def add_to_cart(request, product_id):
    product = get_product(product_id)

    if product is None:
        messages.error(request, "Product not found.")
        return redirect("store:products")

    cart = request.session.get("cart", [])

    if product_id in cart:
        messages.warning(request, f"{product['name']} is already in your cart.")
    else:
        cart.append(product_id)
        request.session["cart"] = cart
        messages.success(request, f"{product['name']} added to cart.")

    return redirect("store:products")
Click Add ↓ Read request.session["cart"] ↓ Modify cart ↓ Save session ↓ messages.success() ↓ redirect() ↓ base.html displays message

14. Remove and Clear Session Data

def remove_from_cart(request, product_id):
    cart = request.session.get("cart", [])
    if product_id in cart:
        cart.remove(product_id)
        request.session["cart"] = cart
        messages.info(request, "Product removed from cart.")
    else:
        messages.warning(request, "Product is not in the cart.")
    return redirect("store:cart")

def clear_cart(request):
    if "cart" in request.session:
        del request.session["cart"]
        messages.success(request, "Cart cleared successfully.")
    else:
        messages.info(request, "The cart is already empty.")
    return redirect("store:cart")

del request.session["cart"] deletes only one session key. request.session.flush() is stronger: it removes the current session data and session identifier.

17. Set Cookies

def preferences(request):
    if request.method == "POST":
        display_name = request.POST.get("display_name", "").strip()
        theme = request.POST.get("theme", "light")

        if theme not in ["light", "dark"]:
            theme = "light"

        response = redirect("store:home")
        response.set_cookie(
            "display_name", display_name,
            max_age=60 * 60 * 24 * 30,
            samesite="Lax"
        )
        response.set_cookie(
            "theme", theme,
            max_age=60 * 60 * 24 * 30,
            samesite="Lax"
        )
        messages.success(request, "Preferences saved.")
        return response

    return render(request, "store/preferences.html")

A cookie is set on the response because the browser receives the response and stores the cookie. 60 * 60 * 24 * 30 represents approximately 30 days in seconds.

18. Read and Delete Cookies

# Read in a view
name = request.COOKIES.get("display_name", "Guest")
theme = request.COOKIES.get("theme", "light")

# Delete
def clear_preferences(request):
    response = redirect("store:home")
    response.delete_cookie("display_name")
    response.delete_cookie("theme")
    messages.info(request, "Saved preferences were cleared.")
    return response

Cookies can also be read in templates through request.COOKIES, as already used in base.html and home.html.

19. Cookie Security

Do not store passwords, secret keys, payment-card data or other secrets in ordinary cookies.

response.set_cookie(
    "example",
    "value",
    max_age=3600,
    httponly=True,
    secure=True,
    samesite="Lax",
)
OptionMeaning
httponlyPrevents normal JavaScript from reading the cookie.
secureSends it only over HTTPS.
samesiteControls cross-site sending behavior.
max_ageLifetime in seconds.

26. What This Exercise Demonstrates

HTTP is stateless ↓ Django request/response ↓ Django Templates ↓ Messages Framework ↓ Sessions ↓ Session Cart + Visit Counter ↓ Cookies ↓ Preferences ↓ Messages + Sessions + Cookies together

The most important distinction is where the information lives and how long it is needed: use messages for short-lived feedback, sessions for visitor-specific server-side state, and cookies for small browser-side values such as preferences.
