1. 🧠 Why MongoDB?

A relational database commonly organizes data into tables, rows and columns. MongoDB is a document database. It stores records as documents and groups related documents into collections.

Relational ideaMongoDB idea
DatabaseDatabase
TableCollection
RowDocument
ColumnField
This is a mental comparison, not a claim that the two systems behave identically. MongoDB has its own document-oriented design.

A movie is a natural document because its related information can stay together:

{
  name: "Inception",
  genre: "Sci-Fi",
  releaseYear: 2010,
  rating: 8.8,
  duration: 148,
  director: "Christopher Nolan"
}
Think of a document as one record about one thing. Here, the thing is a movie.

2. 🧱 Database → Collection → Document → Field

moviehub ← database │ └── movies ← collection │ ├── document ← one movie │ ├── name ← field │ ├── genre ← field │ └── rating ← field │ └── document ← another movie

Database

A logical container for related application data. We use moviehub.

Collection

A group of related documents. We use movies.

Document

One stored record, such as the Inception movie.

Field

A named value inside a document, such as name or rating.

Memory trick: database = application container; collection = group; document = one record; field = one property.

5. 📄 Documents, BSON and Data Types

MongoDB stores documents using BSON, a binary representation of JSON-like documents. In mongosh, the syntax looks familiar because it is JavaScript-like.

{
  name: "Inception",
  genre: "Sci-Fi",
  releaseYear: 2010,
  rating: 8.8,
  duration: 148,
  director: "Christopher Nolan",
  cast: ["Leonardo DiCaprio", "Joseph Gordon-Levitt"]
}
FieldTypeMeaning
nameStringMovie title
genreStringCategory
releaseYearNumberYear
ratingNumberNumeric rating
durationNumberMinutes
castArrayMultiple actors
Data type matters. Store rating: 8.8 as a number when you want numeric comparison and aggregation. A string such as "8.8" is different.

The automatic _id

MongoDB automatically assigns an _id to a document when you do not supply one.

{
  _id: ObjectId("..."),
  name: "Inception",
  ...
}

The _id identifies the document and is especially useful when updating or deleting a specific record.

7. 🔎 READ — Find Documents

Read everything

db.movies.find()

This means: “Return documents from movies without a filtering condition.”

Pretty output

db.movies.find().pretty()

This changes how the result is displayed, not how it is stored.

Find one

db.movies.findOne({ name: "Inception" })

The object { name: "Inception" } is the filter.

find vs findOne: find() returns a cursor over matching documents; findOne() returns one matching document or no result.

8. 🎯 Filtering and Query Operators

Exact match

db.movies.find({ genre: "Sci-Fi" })
Find movies WHERE genre equals "Sci-Fi"

Comparison operators

db.movies.find({ rating: { $gt: 8.5 } })   // greater than
db.movies.find({ rating: { $gte: 8.5 } })  // greater/equal
db.movies.find({ rating: { $lt: 8.5 } })   // less than
db.movies.find({ rating: { $lte: 8.5 } })  // less/equal

The pattern is:

{ field: { operator: value } }

AND-style filtering

db.movies.find({
  genre: "Sci-Fi",
  rating: { $gte: 8.5 }
})

Both conditions must match.

OR

db.movies.find({
  $or: [
    { genre: "Comedy" },
    { genre: "Drama" }
  ]
})

Search an array

db.movies.find({
  cast: "Aamir Khan"
})

MongoDB can match an array field when one of its elements matches the query value.

9. ✏️ UPDATE — Modify Existing Documents

Update one

db.movies.updateOne(
  { name: "Inception" },
  { $set: { rating: 9.0 } }
)

Always read this as two separate ideas:

updateOne( WHICH document? → { name: "Inception" } WHAT change? → { $set: { rating: 9.0 } } )

$set means set the specified field to the specified value.

Update many

db.movies.updateMany(
  { genre: "Sci-Fi" },
  { $set: { featured: true } }
)

Every matching document gets the featured field/value.

Be careful: a broad filter with updateMany() can change many documents. Practice the filter with find() first.

Increment a number

db.movies.updateOne(
  { name: "Dangal" },
  { $inc: { rating: 0.1 } }
)

$inc means increment a numeric field.

10. 🗑️ DELETE — Remove Documents

Delete one

db.movies.deleteOne({ name: "3 Idiots" })

Delete many

db.movies.deleteMany({ genre: "Comedy" })
Safe practice: first run find(filter) to see exactly what matches. Then perform the delete.
db.movies.find({ genre: "Comedy" })

Only after checking the result should you use deleteMany().

12. 🎯 PROJECTION — Decide Which Fields Are Returned

Projection does not delete fields. It controls which fields are included in the query result.

Include fields

db.movies.find(
  {},
  {
    name: 1,
    genre: 1,
    rating: 1
  }
)

The first object is the filter; the second is the projection.

find( FILTER, PROJECTION )

Exclude fields

db.movies.find(
  {},
  {
    cast: 0,
    duration: 0
  }
)

1 means include and 0 means exclude.

Exclude _id

db.movies.find(
  {},
  {
    _id: 0,
    name: 1,
    genre: 1,
    rating: 1
  }
)
Important rule: generally do not mix inclusion and exclusion in one projection. The notable exception is excluding _id while including other fields.

Why projection?

A real document may contain a lot of information. A screen that only needs movie name and rating does not need every field. Projection lets a query return the fields needed for that operation.

13. 🧮 AGGREGATION — Think in Pipelines

Suppose the requirement is “How many movies are there in each genre?” A simple find() retrieves documents, but this requirement asks MongoDB to group and calculate.

Aggregation is used for calculations, grouping, summaries and reports.
Collection ↓ Stage 1 ↓ Stage 2 ↓ Stage 3 ↓ Final report

The stages form a pipeline. The output of one stage becomes the input to the next.

Start an aggregation

db.movies.aggregate([
  {
    $group: {
      _id: "$genre",
      movieCount: { $sum: 1 }
    }
  }
])

Read it slowly:

  1. aggregate() starts the pipeline.
  2. $group groups documents.
  3. _id: "$genre" says the group key is the value of the genre field.
  4. $sum: 1 adds one for every document, creating a count.

14. 🔬 Essential Aggregation Stages

$match — filter documents entering the pipeline

db.movies.aggregate([
  { $match: { rating: { $gte: 8.5 } } }
])

Think: “Which documents should continue?”

$group — group and calculate

db.movies.aggregate([
  {
    $group: {
      _id: "$genre",
      movieCount: { $sum: 1 },
      averageRating: { $avg: "$rating" }
    }
  }
])

Think: “For each group, what calculations do I need?”

$project — shape the pipeline output

db.movies.aggregate([
  {
    $project: {
      _id: 0,
      name: 1,
      rating: 1
    }
  }
])

$sort — order results

db.movies.aggregate([
  { $sort: { rating: -1 } }
])

1 = ascending; -1 = descending.

$limit — keep only N results

db.movies.aggregate([
  { $sort: { rating: -1 } },
  { $limit: 3 }
])
Remember: $match filters → $group calculates → $project shapes → $sort orders → $limit reduces the number of results.

15. 📊 Build Real MovieHub Reports

Report A — Count movies by genre

db.movies.aggregate([
  {
    $group: {
      _id: "$genre",
      count: { $sum: 1 }
    }
  }
])

Report B — Average rating by genre

db.movies.aggregate([
  {
    $group: {
      _id: "$genre",
      averageRating: { $avg: "$rating" },
      movieCount: { $sum: 1 }
    }
  },
  {
    $sort: { averageRating: -1 }
  }
])

Report C — Top five movies

db.movies.aggregate([
  { $sort: { rating: -1 } },
  { $limit: 5 },
  {
    $project: {
      _id: 0,
      name: 1,
      genre: 1,
      rating: 1
    }
  }
])

Read the pipeline as: sort → take five → choose displayed fields.

Report D — Sci-Fi movies rated 8.5 or above

db.movies.aggregate([
  {
    $match: {
      genre: "Sci-Fi",
      rating: { $gte: 8.5 }
    }
  },
  {
    $project: {
      _id: 0,
      name: 1,
      rating: 1,
      director: 1
    }
  }
])

Report E — Total movie duration by genre

db.movies.aggregate([
  {
    $group: {
      _id: "$genre",
      totalMinutes: { $sum: "$duration" }
    }
  },
  {
    $sort: { totalMinutes: -1 }
  }
])

Report F — Minimum and maximum rating by genre

db.movies.aggregate([
  {
    $group: {
      _id: "$genre",
      highestRating: { $max: "$rating" },
      lowestRating: { $min: "$rating" }
    }
  }
])

16. 🔗 Projection vs Aggregation $project

find() projectionAggregation $project
Second argument to find()A pipeline stage
find(filter, projection)aggregate([{ $project: ... }])
Controls returned fieldsShapes documents during pipeline processing

Normal projection

db.movies.find(
  { genre: "Sci-Fi" },
  { _id: 0, name: 1, rating: 1 }
)

Aggregation

db.movies.aggregate([
  { $match: { genre: "Sci-Fi" } },
  { $project: { _id: 0, name: 1, rating: 1 } }
])
Same general idea—shaping fields—but different contexts.

17. 🧩 Nested Documents

MongoDB documents can contain nested objects.

db.movies.insertOne({
  name: "Dune Part Two",
  genre: "Sci-Fi",
  releaseYear: 2024,
  rating: 8.7,
  director: {
    name: "Denis Villeneuve",
    country: "Canada"
  }
})

To query the nested field, use dot notation:

db.movies.find({
  "director.name": "Denis Villeneuve"
})

"director.name" means “go inside the director object and inspect its name field.”

20. 🐛 Common Mistakes

1. Rating stored as text

{ rating: "8.8" }

is not the same type as:

{ rating: 8.8 }

2. Wrong field name

releaseYear and releaseyear are different field names.

3. Dangerous update/delete filter

Before an updateMany/deleteMany, run:

db.movies.find(YOUR_FILTER)

Inspect the matching documents first.

4. Thinking projection deletes fields

It does not. Projection changes what the query returns.

5. Not understanding aggregation order

These are not independent commands. Stage order matters:

documents ↓ $match ↓ filtered documents ↓ $group ↓ grouped/calculated data ↓ $sort ↓ ordered result ↓ $limit ↓ final result

21. 🧠 Final Mental Model

MONGODB │ └── DATABASE │ └── COLLECTION │ └── DOCUMENT │ └── FIELDS CRUD Create → insertOne / insertMany Read → find / findOne Update → updateOne / updateMany Delete → deleteOne / deleteMany PROJECTION "Which fields should I return?" AGGREGATION "How can I process many documents to calculate/group/report something?" PIPELINE $match → $group → $project → $sort → $limit

Five questions to ask yourself

  1. Where is my data? → database/collection.
  2. What is one record? → document.
  3. What information is inside it? → fields.
  4. Am I storing, reading, changing or deleting? → CRUD.
  5. Am I calculating, grouping or reporting? → aggregation.
If you can explain these five questions, you are understanding MongoDB rather than memorizing commands.
