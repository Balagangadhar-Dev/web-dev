Build a Full-Stack Todo Application

A from-scratch, classroom-friendly exercise where You build a real application with a Django backend and a React Vite frontend — while understanding every file, class, function, API request, and piece of state.

🎯 What are we building?

We will build a Todo application where a user can:

➕ Add a taskEnter a title and create a todo.
📋 View tasksReact loads tasks from Django.
✅ Complete a taskToggle completed/pending.
✏️ Edit a taskChange the title.
🗑️ Delete a taskRemove it permanently.
🔄 Refresh safelyData remains in the database.
React UI → HTTP Request → Django REST API → Database
Database → Django REST API → JSON Response → React UI

1. 🧠 Understand the Architecture Before Coding

Do not start by copying code. First understand the jobs of the two applications.

PartResponsibilityTechnology
FrontendShows the interface, accepts user input, displays API data.React + Vite
BackendReceives requests, validates data, performs CRUD operations.Django + Django REST Framework
DatabaseStores todos permanently.SQLite
CommunicationTransfers data between frontend and backend.HTTP + JSON
Important: React does not directly talk to SQLite. React talks to Django through HTTP. Django talks to the database.

The mental model

Imagine a restaurant:

  • React = customer/table — asks for what it wants and displays the result.
  • API = waiter — carries requests and responses.
  • Django = kitchen — decides what should happen.
  • Database = storage room — stores the actual data.

3.3 Create the Todo model

Open todos/models.py:

from django.db import models


class Todo(models.Model):
    title = models.CharField(max_length=200)
    completed = models.BooleanField(default=False)
    created_at = models.DateTimeField(auto_now_add=True)

    def __str__(self):
        return self.title

3.5 Create a serializer

Create a new file: todos/serializers.py

from rest_framework import serializers
from .models import Todo


class TodoSerializer(serializers.ModelSerializer):
    class Meta:
        model = Todo
        fields = ["id", "title", "completed", "created_at"]

Why do we need a serializer?

Django gives us Python objects. The browser normally communicates using JSON. A serializer converts between these representations.

Python Todo object ⇄ TodoSerializer ⇄ JSON

ModelSerializer is a helper class from DRF. It can automatically create many serializer fields from the Django model, reducing repetitive code.

3.6 Create API views

Open todos/views.py:

from rest_framework import generics
from .models import Todo
from .serializers import TodoSerializer


class TodoListCreateView(generics.ListCreateAPIView):
    queryset = Todo.objects.all().order_by("-created_at")
    serializer_class = TodoSerializer


class TodoDetailView(generics.RetrieveUpdateDestroyAPIView):
    queryset = Todo.objects.all()
    serializer_class = TodoSerializer

Understand the generic API views

ClassPurpose
ListCreateAPIViewProvides GET for a list and POST for creating an object.
RetrieveUpdateDestroyAPIViewProvides GET one object, PUT/PATCH update, and DELETE.
querysetTells the view which database records it works with.
serializer_classTells DRF how to convert/validate Todo data.
Why use these classes? We could write all HTTP handling manually, but DRF's generic views already implement common CRUD behavior. The You should understand that this is a reusable framework abstraction, not magic.

5.3 Fetch todos when the component loads

Add this function and effect inside App:

async function fetchTodos() {
  try {
    setLoading(true);
    setError("");

    const response = await fetch(API_URL);

    if (!response.ok) {
      throw new Error("Could not load todos.");
    }

    const data = await response.json();
    setTodos(data);
  } catch (error) {
    setError(error.message);
  } finally {
    setLoading(false);
  }
}

useEffect(() => {
  fetchTodos();
}, []);

Understand the flow:

  1. fetch() sends a GET request.
  2. await waits for the server response.
  3. response.ok checks whether the HTTP response was successful.
  4. response.json() converts JSON into a JavaScript value.
  5. setTodos(data) updates React state.
  6. React re-renders the UI using the new state.

useEffect(..., []) runs after the component's first render because the dependency array is empty.

5.4 Add a Todo

async function addTodo(event) {
  event.preventDefault();

  if (!title.trim()) {
    return;
  }

  try {
    setError("");

    const response = await fetch(API_URL, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        title: title,
        completed: false,
      }),
    });

    if (!response.ok) {
      throw new Error("Could not create todo.");
    }

    const newTodo = await response.json();

    setTodos((currentTodos) => [newTodo, ...currentTodos]);
    setTitle("");
  } catch (error) {
    setError(error.message);
  }
}

Why JSON.stringify? JavaScript objects are not automatically sent as JSON text. JSON.stringify() converts the object into a JSON string suitable for the HTTP request body.

5.5 Toggle completed status

async function toggleTodo(todo) {
  try {
    const response = await fetch(`${API_URL}${todo.id}/`, {
      method: "PATCH",
      headers: {
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        completed: !todo.completed,
      }),
    });

    if (!response.ok) {
      throw new Error("Could not update todo.");
    }

    const updatedTodo = await response.json();

    setTodos((currentTodos) =>
      currentTodos.map((item) =>
        item.id === updatedTodo.id ? updatedTodo : item
      )
    );
  } catch (error) {
    setError(error.message);
  }
}

The map() operation creates a new array. Only the todo whose ID matches the server response is replaced.

5.6 Delete a Todo

async function deleteTodo(id) {
  try {
    const response = await fetch(`${API_URL}${id}/`, {
      method: "DELETE",
    });

    if (!response.ok) {
      throw new Error("Could not delete todo.");
    }

    setTodos((currentTodos) =>
      currentTodos.filter((todo) => todo.id !== id)
    );
  } catch (error) {
    setError(error.message);
  }
}

filter() creates a new array containing every todo except the one with the deleted ID.

7. 🔬 Understand CRUD End-to-End

Create

User types → React state → POST → Django serializer → Todo model → SQLite → JSON → React state

Read

React loads → GET → Django queryset → serializer → JSON → setTodos() → React renders

Update

Checkbox/Edit → PATCH → Django finds object by ID → serializer/model update → JSON → React replaces item

Delete

Delete button → DELETE → Django deletes database row → React filters local list

Why does React update immediately?

React does not need to reload the entire browser page. When setTodos() changes state, React renders the component again using the new state.

This is one of the key ideas You should understand: state is the data that drives the UI.

10. 🔐 Optional Improvement: Better Backend Validation

Once the basic project works, You can learn that backend validation matters even if React already validates the input.

Update todos/serializers.py:

from rest_framework import serializers
from .models import Todo


class TodoSerializer(serializers.ModelSerializer):
    class Meta:
        model = Todo
        fields = ["id", "title", "completed", "created_at"]

    def validate_title(self, value):
        value = value.strip()

        if not value:
            raise serializers.ValidationError(
                "Title cannot be empty."
            )

        return value

Why validate on the backend? A user can bypass React completely and send an HTTP request directly to Django. The server must protect its own data.

Level 4 — Backend filtering

Create an API query such as:

GET /api/todos/?completed=true
