02

Component hierarchy & stateless/stateful components

Break the interface into small pieces with clear responsibilities.

2.1 What is a component?

A React component is a JavaScript function that returns JSX describing a part of the screen. JSX looks like HTML, but it is written inside JavaScript and lets us combine markup with JavaScript expressions.

client/src/App.jsx
function Welcome() {
  return <h1>Welcome to TaskFlow</h1>;
}

export default function App() {
  return (
    <main>
      <Welcome />
      <p>Organize one task at a time.</p>
    </main>
  );
}
function Welcome()
Declares a function component. Component names begin with a capital letter so React can distinguish them from built-in HTML tags.
return (...)
Returns the JSX that React should render. Parentheses make multi-line JSX easier to read.
<Welcome />
Uses one component inside another. This is component composition.
export default
Makes App the default export so the entry file can import it.

2.2 Plan the hierarchy

Appowns shared task data
↓
TaskFormcollects a new task
TaskFilterschooses visible tasks
TaskListrenders task rows
TaskList
↓
TaskItemone task, repeated

This is a component hierarchy: a tree showing which components render other components. A parent can pass information to a child through props. A child can request a parent action by calling a callback function that the parent passed down.

2.3 Stateless vs stateful

Stateless / presentational

Displays what it receives

Does not own the changing task data. Usually receives props and renders them.

JSX
function TaskTitle({ title }) {
  return <h3>{title}</h3>;
}
Stateful

Owns changing information

Uses state because its information changes over time.

JSX
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

These are design descriptions, not rigid categories. A component can receive props and also have its own state. The useful question is: which component should own this piece of changing data?

03

React useState — remembering information

Build the mental model before using state in the full task app.

3.1 Why ordinary variables are not enough

A normal variable can change inside JavaScript, but changing it does not tell React to redraw the screen. React state is information React remembers between renders. When you update state with its setter, React schedules a new render using the updated value.

3.2 useState syntax

React
const [count, setCount] = useState(0);
useState(0)
Calls the Hook and sets the initial value to 0. A Hook is a React function that gives a component a capability such as state or an effect.
count
The current state value for this render.
setCount
The setter used to request a state update. Do not assign directly to count.
[count, setCount]
Array destructuring takes the first and second items returned by useState and gives them useful names.

3.3 Tiny working example

client/src/Counter.jsx
import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);

  function increase() {
    setCount(previousCount => previousCount + 1);
  }

  return (
    <section>
      <p>You clicked {count} times.</p>
      <button onClick={increase}>Increase</button>
    </section>
  );
}

Why use a function updater? setCount(previousCount => previousCount + 1) calculates the next value from the latest queued state. This is a safe pattern when the next state depends on the previous state.

3.4 State with objects and arrays

TaskFlow's tasks are an array. Treat state objects and arrays as immutable: create a new array/object instead of changing the existing one in place.

Correct state updates
// Add an item: create a new array
setTasks(previousTasks => [...previousTasks, newTask]);

// Update one item: map creates a new array
setTasks(previousTasks =>
  previousTasks.map(task =>
    task.id === targetId
      ? { ...task, completed: !task.completed }
      : task
  )
);

// Delete one item: filter creates a new array
setTasks(previousTasks =>
  previousTasks.filter(task => task.id !== targetId)
);
Avoid mutating stateDo not use tasks.push(newTask) and then expect React to notice. It changes the existing array. Prefer [...tasks, newTask] and pass the new array to the setter.

3.5 When should you use state?

Use state for values that change and affect the interface: the task list, text typed into a form, selected filter, loading status, error message, or currently selected task. Do not use state for constants that never change.

04

Event handling in React

React responds to user actions such as clicks, typing and form submission.

4.1 An event is something that happens

A click, key press, input change or form submit is an event. React lets you provide a function that should run when an event occurs.

JSX
function GreetingButton() {
  function sayHello() {
    alert("Hello from TaskFlow!");
  }

  return <button onClick={sayHello}>Say hello</button>;
}
onClick
React event prop for a click. React uses camelCase event names.
onClick={sayHello}
Passes the function to React. React calls it when the button is clicked.
onClick={sayHello()}
This calls the function immediately during rendering, which is usually not what you want for a click handler.

4.2 Event object

JSX
function handleChange(event) {
  console.log(event.target.value);
}

<input onChange={handleChange} placeholder="Type a task" />

The event object describes what happened. event.target is the input that triggered the event; event.target.value is its current text value.

4.3 Controlled input

A controlled input gets its displayed value from React state. The input's value is state, and onChange updates that state as the user types.

JSX
import { useState } from "react";

function NameInput() {
  const [name, setName] = useState("");

  return (
    <label>
      Task name
      <input
        value={name}
        onChange={event => setName(event.target.value)}
      />
      <p>Preview: {name || "Nothing typed yet"}</p>
    </label>
  );
}

4.4 Form submission

JSX
function handleSubmit(event) {
  event.preventDefault(); // stop the browser's full-page form submission
  // Validate the input and create the task here.
}

return (
  <form onSubmit={handleSubmit}>
    <input value={title} onChange={e => setTitle(e.target.value)} />
    <button type="submit">Add task</button>
  </form>
);

preventDefault() stops the browser's default form submission, which would normally navigate/reload the page. React can then handle the action and update the UI.

06

Lifting state up

Move shared state to the closest common parent.

Imagine the task form creates tasks and the task list displays them. If each component has its own separate task array, the form cannot update the list's array. The solution is to put the shared array in their common parent and pass down data and callbacks.

Appowns tasks + setter
↓ props
TaskFormcalls onAddTask(task)
↓ props
TaskListrenders tasks
App.jsx · simplified example
import { useState } from "react";

function TaskForm({ onAddTask }) {
  const [title, setTitle] = useState("");

  function submit(event) {
    event.preventDefault();
    if (!title.trim()) return;
    onAddTask({ id: crypto.randomUUID(), title, completed: false });
    setTitle("");
  }

  return (
    <form onSubmit={submit}>
      <input value={title} onChange={e => setTitle(e.target.value)} />
      <button type="submit">Add</button>
    </form>
  );
}

function TaskList({ tasks }) {
  return <ul>{tasks.map(task => <li key={task.id}>{task.title}</li>)}</ul>;
}

export default function App() {
  const [tasks, setTasks] = useState([]);

  function addTask(task) {
    setTasks(previous => [...previous, task]);
  }

  return (
    <main>
      <TaskForm onAddTask={addTask} />
      <TaskList tasks={tasks} />
    </main>
  );
}
tasks={tasks}
Passes the current array from the parent to the list component.
onAddTask={addTask}
Passes a function. The form can call it, but the parent still controls the actual task array.
key={task.id}
Gives each rendered list item a stable identity so React can track items between renders.

The form keeps its own temporary text state because that text is only needed by the form. The shared task collection belongs in the parent because multiple components need it.

07

useEffect — synchronizing with the outside world

Use effects for work that happens beyond calculating JSX.

7.1 What is an effect?

Rendering should describe the UI for the current props and state. Sometimes the component must synchronize with something outside React: a network request, browser title, timer, subscription or external widget. useEffect runs an effect after React commits a render.

Example
import { useEffect, useState } from "react";

function PageTitleDemo() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `TaskFlow clicks: ${count}`;
  }, [count]);

  return <button onClick={() => setCount(c => c + 1)}>Clicks: {count}</button>;
}
useEffect(() => {...}, [count])
Runs the effect after a render when count changes (and after the initial mount).
[count]
The dependency array lists reactive values used by the effect. React compares them between renders.
[]
An empty dependency array means the effect does not re-run because of changing component values; it runs after the initial mount. Development Strict Mode may intentionally run an extra setup/cleanup cycle.
No dependency array
The effect runs after every render. This is often unnecessary and can cause loops if it updates state each time.

7.2 Cleanup

Timer example
useEffect(() => {
  const timerId = setInterval(() => {
    console.log("Still here");
  }, 5000);

  return () => clearInterval(timerId);
}, []);

The function returned by the effect is called its cleanup. React calls it before re-running the effect and when the component is removed. Clearing a timer prevents it from continuing after it is no longer needed.

Do not use effects for every calculationIf a value can be calculated directly from current props/state (for example, completed task count), calculate it during render. Do not copy it into another state variable using an effect unless there is a specific reason.
08

Async state initialization & loading data

Show how state moves from loading to success or failure.

8.1 What does asynchronous mean?

A network request takes time. JavaScript starts the request and continues doing other work; the response arrives later. The UI should not assume the data is already available. Use state to represent loading, successful data and errors.

loadingshow spinner/message
→
successshow task list
or
errorshow retry message

8.2 Important distinction

useState(initialValue) expects an initial value immediately. Do not pass an async function and expect React to await it. Instead, initialize state with a safe placeholder such as [], then load remote data in an effect or a data-fetching layer.

Async loading pattern
const [tasks, setTasks] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState("");

useEffect(() => {
  async function loadTasks() {
    try {
      const response = await fetch("http://localhost:4000/api/tasks");
      if (!response.ok) throw new Error("Could not load tasks");
      const data = await response.json();
      setTasks(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }

  loadTasks();
}, []);
async function
Declares a function that can use await.
await fetch(...)
Waits for the HTTP response inside this async function without blocking the whole browser.
response.ok
True for HTTP success status codes. fetch does not automatically throw just because the server returns 404 or 500, so check it.
response.json()
Reads the response body and parses JSON into a JavaScript value.
finally
Runs whether the request succeeded or failed, so loading can stop in either case.

8.3 Render each state

JSX
if (loading) return <p>Loading tasks…</p>;
if (error) return <p role="alert">Error: {error}</p>;

return (
  <ul>
    {tasks.map(task => <li key={task._id}>{task.title}</li>)}
  </ul>
);

MongoDB/Mongoose documents commonly use _id instead of a frontend-made id. Use the identifier actually returned by the API consistently.

Express.js and RESTful API basics

The backend receives requests and returns responses.

9.1 What is an API?

An API is a defined way for one program to ask another program to do something. The React app can ask the backend for tasks without directly connecting to the database. The backend owns database access and validation.

9.2 What is REST?

REST is an architectural style often used to design web APIs around resources. Here, the resource is a task. HTTP methods communicate the intended action.

GET/api/tasks/:idRead one task

9.4 Create a Mongoose model

server/models/Task.js
const mongoose = require("mongoose");

const taskSchema = new mongoose.Schema(
  {
    title: {
      type: String,
      required: [true, "Task title is required"],
      trim: true,
      maxlength: [120, "Title cannot exceed 120 characters"]
    },
    description: { type: String, default: "", maxlength: 1000 },
    priority: { type: String, enum: ["low", "medium", "high"], default: "medium" },
    completed: { type: Boolean, default: false }
  },
  { timestamps: true }
);

module.exports = mongoose.model("Task", taskSchema);
mongoose.Schema
Describes the fields expected on each task document.
required
Rejects documents without a title.
trim
Removes whitespace from the beginning and end of the title.
enum
Restricts priority to the listed values.
timestamps: true
Automatically adds createdAt and updatedAt.
mongoose.model("Task", taskSchema)
Creates and exports a model used to query the MongoDB collection.

REST CRUD routes and routing

Create, Read, Update and Delete tasks through HTTP.

10.1 Create a router file

Create server/routes/taskRoutes.js. A router groups related endpoints together so server.js does not become one giant file.

server/routes/taskRoutes.js
const express = require("express");
const mongoose = require("mongoose");
const Task = require("../models/Task");

const router = express.Router();

// READ: get all tasks
router.get("/", async (req, res) => {
  try {
    const tasks = await Task.find().sort({ createdAt: -1 });
    res.json(tasks);
  } catch (error) {
    res.status(500).json({ error: "Could not fetch tasks" });
  }
});

// READ: get one task
router.get("/:id", async (req, res) => {
  try {
    if (!mongoose.isValidObjectId(req.params.id)) {
      return res.status(400).json({ error: "Invalid task id" });
    }
    const task = await Task.findById(req.params.id);
    if (!task) return res.status(404).json({ error: "Task not found" });
    res.json(task);
  } catch (error) {
    res.status(500).json({ error: "Could not fetch task" });
  }
});

// CREATE: add a task
router.post("/", async (req, res) => {
  try {
    const title = typeof req.body.title === "string" ? req.body.title.trim() : "";
    if (!title) return res.status(400).json({ error: "Title is required" });
    const task = await Task.create({
      title,
      description: req.body.description,
      priority: req.body.priority
    });
    res.status(201).json(task);
  } catch (error) {
    if (error.name === "ValidationError") {
      return res.status(400).json({ error: error.message });
    }
    res.status(500).json({ error: "Could not create task" });
  }
});

// UPDATE: change an existing task
router.put("/:id", async (req, res) => {
  try {
    if (!mongoose.isValidObjectId(req.params.id)) {
      return res.status(400).json({ error: "Invalid task id" });
    }
    const allowed = {};
    if (typeof req.body.title === "string") allowed.title = req.body.title.trim();
    if (typeof req.body.description === "string") allowed.description = req.body.description;
    if (["low", "medium", "high"].includes(req.body.priority)) allowed.priority = req.body.priority;
    if (typeof req.body.completed === "boolean") allowed.completed = req.body.completed;
    if (allowed.title === "") return res.status(400).json({ error: "Title cannot be empty" });

    const task = await Task.findByIdAndUpdate(req.params.id, allowed, {
      new: true,
      runValidators: true
    });
    if (!task) return res.status(404).json({ error: "Task not found" });
    res.json(task);
  } catch (error) {
    if (error.name === "ValidationError") return res.status(400).json({ error: error.message });
    res.status(500).json({ error: "Could not update task" });
  }
});

// DELETE: remove a task
router.delete("/:id", async (req, res) => {
  try {
    if (!mongoose.isValidObjectId(req.params.id)) {
      return res.status(400).json({ error: "Invalid task id" });
    }
    const task = await Task.findByIdAndDelete(req.params.id);
    if (!task) return res.status(404).json({ error: "Task not found" });
    res.json({ message: "Task deleted", id: task._id });
  } catch (error) {
    res.status(500).json({ error: "Could not delete task" });
  }
});

module.exports = router;

10.2 Route anatomy

router.get("/", ...)
Handles GET requests to the router's root. Because it is mounted at /api/tasks, the full path is /api/tasks.
router.get("/:id", ...)
The colon makes id a route parameter. Express exposes it as req.params.id.
await Task.find()
Asks MongoDB for matching documents and waits for the asynchronous result.
res.status(201).json(task)
Returns HTTP 201 Created and the created task as JSON.
new: true
Returns the updated document instead of the old version.
runValidators: true
Asks Mongoose to apply schema validators during the update.

11

Introduction to GraphQL

Another way for clients to ask a backend for data.

11.1 What is GraphQL?

GraphQL is a query language for APIs and a runtime that executes those queries against a schema. A client describes the fields it wants, and the server returns a response shaped around that selection. GraphQL is not a database; our resolvers will use the same MongoDB/Mongoose model as REST.

REST example

Client calls a resource endpoint such as GET /api/tasks/123. The server defines the response shape for that endpoint.

Different needs can lead to multiple endpoints or extra fields being transferred.

GraphQL example

Client sends a query describing the fields it needs, such as title and completed.

The schema defines what can be requested and what types are returned.

11.2 Main concepts

Schema
The contract describing available types and operations.
Type
Describes the shape of an object, for example a Task with title and completed fields.
Field
A property that a client can select, such as task.title.
Query
Reads data. Similar purpose to GET in REST, though GraphQL operations are sent to a GraphQL endpoint.
Mutation
Changes data, such as creating, updating or deleting a task.
Resolver
A function that provides the value for a schema field or operation. It might query MongoDB.
Variables
Values supplied separately from the query text, making operations reusable and easier to validate.

11.3 Benefits and trade-offs

Benefits

  • Request only the fields needed.
  • One schema can expose related data through a consistent API.
  • Types make the API contract explicit.
  • Queries and mutations are structured.

Trade-offs

  • Requires schema and resolver design.
  • Authorization must be checked carefully.
  • Complex queries can be expensive without limits.
  • HTTP caching can require more deliberate setup than simple GET endpoints.
REST and GraphQL can coexistFor this exercise, keep REST CRUD routes and add GraphQL at /graphql. Both interfaces call the same Mongoose model. This makes it possible to compare them without rewriting the database layer.

12.2 Build a schema and resolvers

Create server/graphql/schema.js. The schema and resolvers below are written to work with the Task model created earlier.

server/graphql/schema.js
const { buildSchema } = require("graphql");
const mongoose = require("mongoose");
const Task = require("../models/Task");

const schema = buildSchema(`
  type Task {
    id: ID!
    title: String!
    description: String!
    priority: String!
    completed: Boolean!
    createdAt: String!
    updatedAt: String!
  }

  input TaskInput {
    title: String
    description: String
    priority: String
    completed: Boolean
  }

  type Query {
    tasks: [Task!]!
    task(id: ID!): Task
  }

  type Mutation {
    createTask(input: TaskInput!): Task!
    updateTask(id: ID!, input: TaskInput!): Task
    deleteTask(id: ID!): Boolean!
  }
`);

function toGraphQLTask(task) {
  if (!task) return null;
  return {
    id: task._id.toString(),
    title: task.title,
    description: task.description || "",
    priority: task.priority,
    completed: task.completed,
    createdAt: task.createdAt?.toISOString() || null,
    updatedAt: task.updatedAt?.toISOString() || null
  };
}

const root = {
  tasks: async () => {
    const tasks = await Task.find().sort({ createdAt: -1 });
    return tasks.map(toGraphQLTask);
  },
  task: async ({ id }) => {
    if (!mongoose.isValidObjectId(id)) return null;
    const task = await Task.findById(id);
    return toGraphQLTask(task);
  },
  createTask: async ({ input }) => {
    const title = typeof input.title === "string" ? input.title.trim() : "";
    if (!title) throw new Error("Title is required");
    const task = await Task.create({
      title,
      description: input.description || "",
      priority: input.priority || "medium",
      completed: input.completed ?? false
    });
    return toGraphQLTask(task);
  },
  updateTask: async ({ id, input }) => {
    if (!mongoose.isValidObjectId(id)) throw new Error("Invalid task id");
    const updates = {};
    if (input.title !== undefined) updates.title = input.title.trim();
    if (input.description !== undefined) updates.description = input.description;
    if (input.priority !== undefined) updates.priority = input.priority;
    if (input.completed !== undefined) updates.completed = input.completed;
    if (updates.title === "") throw new Error("Title cannot be empty");
    const task = await Task.findByIdAndUpdate(id, updates, { new: true, runValidators: true });
    return toGraphQLTask(task);
  },
  deleteTask: async ({ id }) => {
    if (!mongoose.isValidObjectId(id)) throw new Error("Invalid task id");
    const deleted = await Task.findByIdAndDelete(id);
    return Boolean(deleted);
  }
};

module.exports = { schema, root };

12.3 Understand the schema

buildSchema(`...`)
Parses the GraphQL schema definition language (SDL) and creates a schema object.
type Task
Defines the fields available on a Task result. The resolver converts MongoDB's _id into a string called id.
input TaskInput
Defines a reusable object shape for data supplied to create/update mutations. Input types are for incoming data; object types are for returned data.
type Query
Lists read operations that clients may request.
type Mutation
Lists operations that change data.
root
Contains resolver functions. With this simple buildSchema setup, the matching resolver functions are properties on the root value.
toGraphQLTask
Transforms a Mongoose document into a plain object with the field names and values promised by the GraphQL schema.
Field specification mattersGraphQL clients can select only fields declared by the schema. The schema is a contract, not a direct view of every MongoDB field. Keep schema fields and resolver results consistent.

GraphQL queries & query variables

Read exactly the fields the caller needs.

13.1 Query all tasks

GraphQL query
query GetTasks {
  tasks {
    id
    title
    completed
    priority
  }
}

query labels this as a read operation. GetTasks is an optional operation name that helps with debugging. Inside tasks, the client explicitly selects the fields it wants.

13.2 Query one task

GraphQL query
query GetOneTask {
  task(id: "PASTE_A_REAL_TASK_ID_HERE") {
    id
    title
    description
    completed
  }
}

Replace the placeholder with a real MongoDB task ID. A GraphQL ID is an identifier scalar; in this project it maps to the MongoDB ObjectId string.

13.3 Why variables?

Hard-coding a value inside the query means editing the query whenever the value changes. Variables separate the operation from its input.

Query document
query GetOneTask($taskId: ID!) {
  task(id: $taskId) {
    id
    title
    completed
  }
}
Variables JSON
{
  "taskId": "PASTE_A_REAL_TASK_ID_HERE"
}

$taskId is a variable declared in parentheses. ID! means the caller must supply a non-null identifier. The JSON object provides its value. Variables reduce string-building errors and make queries reusable.

13.4 Try GraphQL over HTTP

Our endpoint will be http://localhost:4000/graphql. The following curl request sends a query as JSON. Use a terminal that supports single-quoted JSON (macOS/Linux/Git Bash); in other shells, use their appropriate quoting.

Terminal · GraphQL query
curl -X POST http://localhost:4000/graphql \
  -H "Content-Type: application/json" \
  -d '{"query":"query { tasks { id title completed priority } }"}'

GraphQL responses commonly contain a data field. If an operation fails during execution, the response may also include an errors array. Do not assume every HTTP 200 response means the GraphQL operation succeeded.

  }

Supply the existing task ID and only the fields you want to change in input. The resolver returns the updated record or null if the ID is valid but no task exists. A production API should define and document its not-found error convention consistently.

14.3 Delete a task

Mutation
mutation DeleteTask($id: ID!) {
  deleteTask(id: $id)
}

This mutation returns a Boolean: true if a document was deleted, false if there was no matching document. Invalid IDs throw an error in our resolver.

Why do mutations return fields?A mutation can return the created or updated object, allowing the frontend to use the server's authoritative data (including its ID and timestamps) instead of guessing what was saved.

15.3 React error handling pattern

Reusable API helper
async function requestJson(url, options = {}) {
  const response = await fetch(url, {
    ...options,
    headers: {
      "Content-Type": "application/json",
      ...(options.headers || {})
    }
  });

  const data = await response.json().catch(() => ({}));

  if (!response.ok) {
    throw new Error(data.error || `Request failed (${response.status})`);
  }

  return data;
}

This helper centralizes repetitive work: send the request, parse JSON, check the status and throw an understandable error. The component using it can catch that error and show it to the user.

15.4 GraphQL error handling

GraphQL distinguishes errors such as invalid query syntax/schema validation from errors thrown by resolvers during execution. The response often includes errors with messages and may include partial data. Avoid exposing stack traces, database credentials or sensitive internals to clients. Log detailed diagnostics on the server and send safe messages to users.

Security noteThis is a learning application, not a production-ready public API. Before deployment, add authentication, authorization, request limits, stronger validation, safe logging, rate limiting and GraphQL query depth/complexity controls. CORS alone does not protect an API.

16.3 React integration: load tasks from REST

To make the frontend concrete, replace client/src/App.jsx with the beginner-sized working version below. It loads, creates, completes and deletes tasks through the REST API. You can add edit/filter styling after the data flow is working.

client/src/App.jsx
import { useEffect, useState } from "react";
import "./App.css";

const API = "http://localhost:4000/api/tasks";

export default function App() {
  const [tasks, setTasks] = useState([]);
  const [title, setTitle] = useState("");
  const [priority, setPriority] = useState("medium");
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState("");

  async function loadTasks() {
    setLoading(true);
    setError("");
    try {
      const response = await fetch(API);
      if (!response.ok) throw new Error("Unable to load tasks");
      setTasks(await response.json());
    } catch (err) {
      setError(err.message || "Network error");
    } finally {
      setLoading(false);
    }
  }

  useEffect(() => {
    loadTasks();
  }, []);

  async function addTask(event) {
    event.preventDefault();
    if (!title.trim()) {
      setError("Please enter a task title.");
      return;
    }
    try {
      const response = await fetch(API, {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ title: title.trim(), priority })
      });
      const data = await response.json();
      if (!response.ok) throw new Error(data.error || "Could not add task");
      setTasks(previous => [data, ...previous]);
      setTitle("");
      setPriority("medium");
      setError("");
    } catch (err) {
      setError(err.message);
    }
  }

  async function toggleTask(task) {
    try {
      const response = await fetch(`${API}/${task._id}`, {
        method: "PUT",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ completed: !task.completed })
      });
      const updated = await response.json();
      if (!response.ok) throw new Error(updated.error || "Could not update task");
      setTasks(previous => previous.map(item => item._id === updated._id ? updated : item));
    } catch (err) {
      setError(err.message);
    }
  }

  async function deleteTask(id) {
    try {
      const response = await fetch(`${API}/${id}`, { method: "DELETE" });
      const data = await response.json();
      if (!response.ok) throw new Error(data.error || "Could not delete task");
      setTasks(previous => previous.filter(task => task._id !== id));
    } catch (err) {
      setError(err.message);
    }
  }

  const completedCount = tasks.filter(task => task.completed).length;

  return (
    <main className="app-shell">
      <header className="hero-panel">
        <p className="eyebrow">YOUR PERSONAL WORKSPACE</p>
        <h1>TaskFlow</h1>
        <p>Turn the next small step into progress.</p>
        <div className="stats">
          <span>Total tasks: <strong>{tasks.length}</strong></span>
          <span>Completed: <strong>{completedCount}</strong></span>
        </div>
      </header>

      <form className="task-form" onSubmit={addTask}>
        <label>Task title
          <input value={title} onChange={e => setTitle(e.target.value)} placeholder="e.g. Learn useEffect" maxLength={120} />
        </label>
        <label>Priority
          <select value={priority} onChange={e => setPriority(e.target.value)}>
            <option value="low">Low</option>
            <option value="medium">Medium</option>
            <option value="high">High</option>
          </select>
        </label>
        <button type="submit">+ Add task</button>
      </form>

      {error && <p className="error" role="alert">{error}</p>}
      {loading ? <p>Loading tasks…</p> : tasks.length === 0 ? (
        <p className="empty">No tasks yet. Add your first one above.</p>
      ) : (
        <section className="task-list">
          {tasks.map(task => (
            <article className={`task-card ${task.completed ? "completed" : ""}`} key={task._id}>
              <label className="task-main">
                <input type="checkbox" checked={task.completed} onChange={() => toggleTask(task)} />
                <span>
                  <strong>{task.title}</strong>
                  <small>Priority: {task.priority}</small>
                </span>
              </label>
              <button className="delete" type="button" onClick={() => deleteTask(task._id)}>Delete</button>
            </article>
          ))}
        </section>
      )}
    </main>
  );
}

Debugging guide & common mistakes

Use the symptom to narrow down the layer where the problem exists.

SymptomLikely reasonWhat to check
Frontend cannot connectBackend stopped or wrong URL/port.Open /api/health; inspect terminal errors.
CORS errorFrontend origin not allowed.Check the configured origin matches the Vite URL.
MongoDB connection errorMongoDB is stopped or URI is wrong.Check MONGODB_URI and MongoDB service.
Request body is undefinedJSON middleware missing or wrong Content-Type.Use app.use(express.json()) before routes and send JSON header.
Screen does not updateState mutated directly or setter not called.Use immutable array/object updates and the setter.
Infinite effect requestsEffect updates a dependency that causes it to run again.Review dependencies and avoid setting state unnecessarily in every render.
GraphQL unknown fieldQuery asks for a field absent from the schema.Compare query fields with the schema.
GraphQL data is nullResolver returned null, or an error affected a non-null field.Inspect both data and errors.
Invalid task IDMalformed MongoDB ObjectId.Copy the exact _id from a returned document.
Task creation returns 400Missing title or invalid priority.Inspect request body and Mongoose validation message.

Recommended debugging sequence

  1. Check the browser console. Read the first meaningful error; it often points to the component or line that failed.
  2. Check the backend terminal. Look for syntax errors, failed database connections and rejected requests.
  3. Test the API without React. Use curl/Postman to see whether the backend works independently.
  4. Inspect the request. Confirm URL, HTTP method, headers and JSON body.
  5. Inspect the response. Check status code, returned JSON and any error field.
  6. Verify the database. Confirm that the document was created/updated/deleted in MongoDB.

Final mental model

React state controls what the user sees. Props pass data and callbacks between components. useEffect synchronizes with external systems such as APIs. Express defines backend HTTP routes. REST organizes operations around resources and HTTP methods. GraphQL exposes a typed schema with queries for reading and mutations for changing data. Mongoose/MongoDB stores the persistent records.

Once you can follow a task from the button click to the database and back to the screen, you understand the central full-stack data flow.
