Django + Local MongoDB

Connect an existing Django Movie application to a locally running MongoDB database and migrate the existing SQLite data. This practical explains the connection, commands, model mapping, Movie migration, Django User migration, password hashes, and verification from A–Z.

1. What You Will Build

Current application:

Django→SQLite

Target application:

Django→Django MongoDB Backend→Local MongoDB

Data migration:

SQLite→Python export→JSON→Python import→MongoDB
  • Connect Django to MongoDB running on your computer.
  • Understand database, collection, document and field.
  • Move the existing Movie records.
  • Move existing Django users.
  • Preserve existing password hashes so old passwords still work.
  • Test old login, new signup and Movie CRUD.
Important current limitation: the official Django MongoDB Backend currently lists dumpdata and loaddata as unsupported. Therefore this exercise does not pretend that a normal Django fixture can simply be loaded into MongoDB. 4.2 settings.py

Replace SQLite:

    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}

with:

        "NAME": "moviehub",
    }
}

The official connection guide uses django_mongodb_backend for ENGINE and accepts the MongoDB URI in HOST. citeturn0search1

4.3 Understand the configuration

  • ENGINE tells Django which database backend to use.
  • HOST tells the backend where MongoDB is running.
  • NAME is the MongoDB database name.

5. Your Movie Model

from django.db import models

class Movie(models.Model):
    name = models.CharField(max_length=200)
    genre = models.CharField(max_length=100)
    releaseYear = models.IntegerField()
    rating = models.CharField(max_length=20)
    duration = models.CharField(max_length=20)
    director = models.CharField(max_length=100)
    cast = models.TextField()
    description = models.TextField()
    bannerUrl = models.URLField()
    trailer = models.URLField()

With the MongoDB backend, a Django model represents data stored in a MongoDB collection. The official documentation shows models being mapped to collections and migrations being used to create them. citeturn0search8

5.1 Important primary-key difference

SQLite projects commonly use integer IDs. MongoDB commonly uses ObjectIds. Do not assume an old SQLite integer ID should simply become a MongoDB ObjectId. The migration below creates MongoDB-backed records and preserves the old ID only as information if you need it.

For supported ORM operations, your code remains familiar:

Movie.objects.all()
Movie.objects.filter(genre="Drama")
Movie.objects.create(...)

The official backend provides Django ORM interaction with MongoDB. citeturn0search11

6.3 Create Movie export command

movies/
  management/
    __init__.py
    commands/
      __init__.py
      export_sqlite_data.py
import json
from django.core.management.base import BaseCommand
from movies.models import Movie

class Command(BaseCommand):
    help = "Export Movie data from SQLite to JSON"

    def handle(self, *args, **options):
        movies = Movie.objects.all()
        data = []

        for movie in movies:
            data.append({
                "old_id": movie.id,
                "name": movie.name,
                "genre": movie.genre,
                "releaseYear": movie.releaseYear,
                "rating": movie.rating,
                "duration": movie.duration,
                "director": movie.director,
                "cast": movie.cast,
                "description": movie.description,
                "bannerUrl": movie.bannerUrl,
                "trailer": movie.trailer,
            })

        with open("movies_migration.json", "w", encoding="utf-8") as file:
            json.dump(data, file, indent=2)

        self.stdout.write(
            self.style.SUCCESS(f"Exported {len(data)} movies")
        )

Why each part? BaseCommand creates a custom manage.py command; Movie.objects.all() reads SQLite records; the Python dictionary converts each model object into portable JSON data; json.dump() writes the file.

python manage.py export_sqlite_data

6.4 Export users

movies/management/commands/export_users.py
import json
from django.contrib.auth.models import User
from django.core.management.base import BaseCommand

class Command(BaseCommand):
    help = "Export Django users from SQLite to JSON"

    def handle(self, *args, **options):
        users = User.objects.all()
        data = []

        for user in users:
            data.append({
                "old_id": user.id,
                "username": user.username,
                "email": user.email,
                "password": user.password,
                "first_name": user.first_name,
                "last_name": user.last_name,
                "is_staff": user.is_staff,
                "is_active": user.is_active,
                "is_superuser": user.is_superuser,
                "date_joined": user.date_joined.isoformat(),
                "last_login": user.last_login.isoformat() if user.last_login else None,
            })

        with open("users_migration.json", "w", encoding="utf-8") as file:
            json.dump(data, file, indent=2)

        self.stdout.write(
            self.style.SUCCESS(f"Exported {len(data)} users")
        )
python manage.py export_users
Password explanation: user.password is a Django password hash, not the original password. Preserving that hash lets the same password continue to authenticate after migration.
Security: the user JSON contains personal information and password hashes. Never publish it or commit it to Git.

9. Import Movie Data Into MongoDB

Because loaddata is unsupported by the current backend, write a custom import command. citeturn0search0

movies/management/commands/import_movies_to_mongodb.py
import json
from django.core.management.base import BaseCommand
from movies.models import Movie

class Command(BaseCommand):
    help = "Import Movie data into MongoDB"

    def handle(self, *args, **options):
        with open("movies_migration.json", "r", encoding="utf-8") as file:
            data = json.load(file)

        imported = 0

        for item in data:
            Movie.objects.create(
                name=item["name"],
                genre=item["genre"],
                releaseYear=item["releaseYear"],
                rating=item["rating"],
                duration=item["duration"],
                director=item["director"],
                cast=item["cast"],
                description=item["description"],
                bannerUrl=item["bannerUrl"],
                trailer=item["trailer"],
            )
            imported += 1

        self.stdout.write(
            self.style.SUCCESS(f"Imported {imported} movies into MongoDB")
        )

How it works: json.load() converts the file into Python data; the loop reads one Movie at a time; Movie.objects.create() creates a MongoDB-backed document through Django.

python manage.py import_movies_to_mongodb

10. Migrate Existing Django Users

10.1 What must be preserved?

  • username
  • email
  • first/last name
  • active/staff/superuser flags
  • date joined and last login
  • password hash

10.2 Why the password still works

If the user originally typed:

MySecretPassword123

Django stores a hash, such as:

pbkdf2_sha256$...

We migrate the hash, not the plain-text password. Django can then compare the password entered at login against the stored hash.

10.3 Import command

movies/management/commands/import_users_to_mongodb.py
import json
from datetime import datetime
from django.contrib.auth import get_user_model
from django.core.management.base import BaseCommand

class Command(BaseCommand):
    help = "Import existing Django users into MongoDB"

    def handle(self, *args, **options):
        User = get_user_model()

        with open("users_migration.json", "r", encoding="utf-8") as file:
            data = json.load(file)

        imported = 0

        for item in data:
            user = User(
                username=item["username"],
                email=item["email"],
                password=item["password"],
                first_name=item["first_name"],
                last_name=item["last_name"],
                is_staff=item["is_staff"],
                is_active=item["is_active"],
                is_superuser=item["is_superuser"],
            )

            user.date_joined = datetime.fromisoformat(item["date_joined"])

            if item["last_login"]:
                user.last_login = datetime.fromisoformat(item["last_login"])

            user.save()
            imported += 1

        self.stdout.write(
            self.style.SUCCESS(f"Imported {imported} users into MongoDB")
        )

10.4 Why get_user_model()?

It asks Django for the User model configured by the project instead of hard-coding a model class.

10.5 Very important: do NOT hash the hash again

This is correct for an already-hashed password:

user.password = item["password"]
user.save()

Do not do this:

user.set_password(item["password"])

set_password() is for a plain-text password. Calling it on an existing hash would hash the hash and break the old password.

python manage.py import_users_to_mongodb

11. Your Existing Login/Signup Code

Your authentication code remains conceptually the same.

Login

from django.contrib.auth import authenticate, login

def loginPage(request):
    if request.method == "POST":
        username = request.POST["username"]
        password = request.POST["password"]

        user = authenticate(
            request,
            username=username,
            password=password
        )

        if user is not None:
            login(request, user)
            return redirect("home")

        return render(request, "login.html", {
            "error": "Invalid Username or Password"
        })

    return render(request, "login.html")
username + password→authenticate()→User model→MongoDB

Signup

user = User.objects.create_user(
    username=username,
    email=email,
    password=password
)
login(request, user)

create_user() receives the plain password and hashes it before saving. This is different from the migration script, where we already have the old hash.

Logout

from django.contrib.auth import logout

def logoutPage(request):
    logout(request)
    return redirect("login")

Existing sessions

A user account and a browser login session are different. This exercise preserves accounts and password hashes. It does not attempt to preserve every old browser session. Users may need to log in again after the migration.

13. Troubleshooting

Connection refused on 127.0.0.1:27017

MongoDB server is not running or is not listening on the expected port. Confirm that mongosh connects.

ModuleNotFoundError: django_mongodb_backend
pip install django-mongodb-backend

Also verify that the backend version matches Django. citeturn0search10

dumpdata/loaddata fails

The current official backend lists these commands as unsupported. Use the custom export/import commands in this exercise. citeturn0search0

Old password no longer works
  • Confirm the original user.password hash was exported.
  • Do not call set_password() on the already-hashed value.
  • Make sure the user was imported only once.
  • Test through the normal login page.
Movie count is wrong
  • Compare with the SQLite count recorded before migration.
  • Check whether the import command ran twice.
  • Use a fresh target database for a clean practice run.
Authentication/admin behaves differently

The backend has documented compatibility limitations. Django contrib apps can require MongoDB-specific configuration depending on your Django/backend version. Follow the official migration guidance for your exact version. citeturn0search2

Project has many foreign keys

A relational project with many foreign keys, many-to-many relations and through models needs a more carefully designed migration. This exercise focuses on the supplied Movie model and Django User data.

15. Final Mental Model

Old Django→SQLite→Export Python data→JSON→Import→MongoDB

You are not copying the SQLite database file into MongoDB. You are reading old records, transforming them into MongoDB-backed Django objects, and creating new documents.

Browser→Django Views→Django ORM→Django MongoDB Backend→PyMongo→MongoDB
Most important lesson: the database technology changes underneath the Django application, but the application still works through Django models, QuerySets and authentication APIs wherever the MongoDB backend supports those features.
